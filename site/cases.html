案例 1 · 自举（用 CodeFlow 开发 CodeFlow）✅ 真实闭环实测

生产上的登录功能，是数字员工写的

项目背景

我们自己的社区版平台（生产环境在跑）要加「会员登录页记住我」功能，随后又来了一条缺陷：「勾选后刷新页面，勾选状态丢失」。两件事都走 CodeFlow——我们没有自己写。

发生了什么

禅道建单 → 数字员工自主定位真实 git 仓库，自建分支 feat/10007-remember-me：LoginPage 80 行、新建 RememberMeService、3 个测试类，推送分支。缺陷单 52 分钟修复，工单「已关闭」，修复报告幂等回写禅道。

价值：现在生产上跑的这个功能，就是数字员工的交付物——自举不是概念，是我们的日常。

案例 2 · 需求澄清✅ 真实闭环实测

在工单里直接问，数字员工实时读单后开工

场景

需求写得不清不楚，传统做法是拉会、约时间、来回传话——澄清成本常常比开发还高。

适合：需求方和开发不在一地、需求描述天然模糊的远程协作。

怎么用 CodeFlow

在工单里直接与数字员工对话：它经平台 MCP 实时读取工单（标题、状态、外部来源）后作答与追问——上面案例 1 的真实闭环里，复现路径就是这么澄清出来的。事实不清时它会主动问，而不是自作主张。

价值：澄清发生在工单里，留下文字记录，开工口径有据可查。

案例 3 · 从零到可运行✅ 真实闭环实测

真模型 12 分钟交付一个完整小工具

项目背景

一个独立小需求（内部脚本、工具页、小功能），不值得占用整块人力，但要"真的能跑"。

发生了什么

工单写清需求 → 8 秒内派发受理 → 4 步 SDLC 12 分钟跑完 → 可运行代码 + 19 个单元测试全过 + 自动 git 初始化 + 全套文档。边界诚实：坏模型名 40 秒如实 FAILED 交回真人。

价值：小需求不再排队等人，也不用接受一段跑不起来的伪代码。

案例 4 · 多角色流水线✅ 真实闭环实测

开发者 → 评审，双角色零人工接棒

项目背景

评审要求严格的团队，流水线每个角色之间都要人工重新指派——"一个人盯一条流水线"。

发生了什么

双人小队（Developer + Reviewer，workflow 模板定义职责与证据引用）→ SDLC 步骤间自动接棒：成功进下一步、失败按预算重试、END 自动到达 DONE。实测全链路零人工重新指派。

价值：评审门槛没有降——降的是"催活"的人力。

案例 5 · 生产环境实证📄 生产环境实际发生

一台 2 核 2G 的机器，长期跑着 CodeFlow 社区版

项目背景

客户常说：先低成本试起来，数据不能出域。我们的答案不是 PPT，是这台跑了很久的生产机。

实际状态

同一台 2C2G 服务器上：CodeFlow 社区版平台 + MySQL / Redis / MinIO / SeekDB 数据底座，全部自托管在跑；执行器 runtime 纯标准库（Python 3.11）独立部署；模型接任意 Anthropic 兼容端点，账单走自己的 key。

价值：私有化不是降配演示，是可长期运行的生产形态。

案例 6 · 开源协作📄 生产环境实际发生

外部开发者 fork 仓库，给官网加上了视频

项目背景

官网开源上线的第一周，一位外部开发者（BPCKeeeeeepOn）fork 了官网仓库，新建分支，给首页做了产品演示视频区块并推送——从 fork 到推送当天完成。

发生了什么

我们逐文件审查（视频 8.6MB、播放器实现 preload=none 点击才加载），合入上游 main，当天部署上线。全程标准开源协作流：fork → 分支 → 审查 → 合入。

价值：官网本身就是 CodeFlow 生态的第一个开源协作现场——欢迎你也来。
