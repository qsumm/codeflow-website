主链路

从告警到恢复，每一步都留下可追溯的痕迹

三段主链路，难点从来不是功能，是可信度——凭什么信 AI 说的、凭什么敢让它动。

STEP 01 / 发现

Agent 接管监控

STEP 02 / 告警

指纹去重，只报一次

同一次故障不会刷屏成二十条告警。

  • 阈值 / 3σ / 孤立森林 三类检测
  • 指纹状态机 + 留观恢复窗口

STEP 03 / 定位

AI 自主排查取证

  • 两级收敛，一次故障一个事件
  • ReAct 循环 + 预算五件套兜底
  • 每条结论强制带证据 token

护栏内才准动手

  • 九道护栏 + 动作清单

差异点

别人的 AI 给你结论，
我们给你证据。

AI 写的报告最常见的失败不是"写错"，是"写得像对的"—— 业务码 0、状态字段 3、合作状态 1，看着全对，但你追问"这个 3 从哪来的"，它答不上来。

  • 1结论必须带证据 token。每条「受影响实体」都要挂一个 step_N，点得回原始工具调用的输入输出。没有引用的结论不允许出现在报告里。
  • 2不确定就写不确定。置信度按已采集证据来源确定性计分，不是让模型自己给自己打分；关键证据缺失时置信度封顶。
  • 3反过早收敛。提示词里写死了"时间吻合≠因果""最常见因≠本次因""could is not did"三条陷阱清单，穷尽之后才允许给 INCONCLUSIVE。
  • 4把没查的也说清楚。影响面强制四分类：已确认受影响 / 已确认健康 / 窗口内因其它原因变化 / 没检查。最后一项不能省。
  • 5结论可复现。工具响应可固化为快照，回放时 LLM temperature=0 跑同一段上下文——改提示词前后能出对比矩阵，不是"感觉变好了"。

处置

FR-E

AI 永远不能直接执行命令——这是设计，不是配置。

  • 九道护栏：禁用清单 / 只读白名单 / 爆炸半径 / 幂等 …
  • 三档执行：仅建议 / 人工确认 / 白名单自动
  • 一次性凭据：只存 sha256、TTL 300s、用后即焚、重放被拒
  • 审计可追溯：谁在何时以何种方式批准了哪一步
  • 分级恢复：4 类动作白名单 + 连续失败熔断

FAQ

常见问题

我管着 5 台机器，需要这个吗？

5 台以下基本不需要——传统的轻量监控工具都够，AI 诊断没有数据可吃。本平台的核心场景在 5~50 台：批量探活、护栏、跨主机诊断的收益最大。500 台以上也适合，但要评估接入路径（逐台装 Agent 慢，可走 Prometheus 数据源 + node_exporter 直采）。

一定要绑定某家大模型吗？

不需要。平台支持多模型配置，可按角色设置不同模型与参数，并提供连接测试，便于替换与成本控制。DeepSeek / 通义千问 / 硅基流动 / OpenAI 兼容网关都能接，也可自建。

AI 会不会自己上生产机乱动？

不会，而且这是写进代码的硬约束。九道护栏里第一条就是禁用清单（rm -rf /、mkfs、dd 写盘、管道进 shell 等）；只读白名单之外的动作必须先由人签发一次性凭据，凭据用后即焚、重放被拒。平台 V1 不代运维在目标机执行命令，远程执行通道列入 V2 路线。

怎么保证 AI 报告不是编的？

四条机制叠加：① 每条「受影响实体」必须带证据 token，点得回原始工具调用；② 置信度按证据来源确定性计分，不是模型自评；③ 提示词内置反过早收敛陷阱清单，穷尽后才允许 INCONCLUSIVE；④ 评测闭环用快照回放，改提示词前后能出对比矩阵。历史上抓到过的真实问题（模型写对了却被解析器判废、白名单被 `cat > file` 绕过）都有回归测试锁住。

数据会不会传到别人的服务器？

取决于你怎么部署。自托管时数据只在你自己的机器上；调用大模型时只有诊断上下文会发给 LLM 提供方，平台提供脱敏与最小化。平台自身的采集与存储不做任何外传，通知只走你配置的渠道。

怎么验证它真的能用，而不是 demo？

仓库自带 5 种故障注入脚本（CPU 飙高 / 磁盘打满 / 进程假死 / 探活失败 / 内存泄漏），一条命令触发、观察完整链路。另有主流程冒烟脚本可作为部署 gate。注意：故障脚本不要在生产机上跑——它们会真的占满资源。
