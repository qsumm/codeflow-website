部署指南

三条路，一条命令起步。

以下命令与产品仓库《快速开始》逐字一致（构建时自动抽取对账）。首次构建约 3~6 分钟。

开源路径

Docker Compose 一键部署

bash — 快速开始（与产品仓逐字一致）
docker compose version
free -m | head -2
df -h / | tail -1
①

前置条件

  • Linux x86_64/aarch64 或 macOS · Docker 20.10+ 与 Compose v2
  • 可用内存 ≥ 4GB（数据库是 OceanBase 系，2GB 勉强）
  • 端口 8848 未占用；2891（数据库）只做本机映射，不对外开放
  • 出站可达 Docker Hub（不可达时用镜像源 build-arg，见下）
②

安全红线（违反即部署失败）

  • 三个默认密钥一个都不许留默认值：JWT_SECRET / KEY_STORE_SECRET / DB_PASSWORD 换成随机值
  • 不要在公网开放 2891 端口
  • 不要在生产环境执行 deploy/faults/ 下的任何故障注入脚本
  • 登录后第一件事改 admin 默认密码
③

实测常见坑

  • --env-file .env 必须带：compose 项目目录会变成 deploy/，不带则根 .env 读不到，LLM 与密钥全空
  • SeekDB 数据目录是 /var/lib/seekdb（命名卷 seekdb-data）；down -v 会清数据
  • 服务器时间不同步会导致告警时间窗错乱，部署前先对时
  • 国内拉不动 Docker Hub：--build-arg APT_MIRROR=mirrors.aliyun.com --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
  • 接入被监控机：平台「主机管理 → 接入新主机」复制安装命令；目标机 macOS/Linux + Python ≥3.9，无需开放入站端口；可先跑只读 preflight 自检
演示与验证

灌种子数据，注入一次真实故障

故障注入脚本场景恢复

mem_leak.sh内存泄漏自动恢复
disk_full.sh磁盘打满（安全上限内写入）自动恢复
probe_fail.sh探活失败自动恢复

⚠ 脚本只用于演示环境——它们会真的占满资源，不要在生产机运行。
