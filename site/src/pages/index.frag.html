按完整指南开始 →
1

起 CodeFlow 平台

准备一台 4C8G 的机器（Docker + Docker Compose），克隆仓库并构建。

git clone {{REPO_CLONE}} && cd CodeFlow/platform bash build.sh && bash bootstrap.sh
2

注册首个用户

打开注册页建组织，即成为管理员。

http://localhost:7001/register
3

接入执行器

在执行器节点（2C2G 即可）注册 runtime，接上你自己的模型通道。

python scripts/register_executor.py --agent-id 10001 \ --workspace-id 10000 --out runtime.env --provider claude
4

派第一个需求

在工单里指派数字员工，或绑定你的工单平台让需求自动流进来——剩下的交付在平台上看。

常见问题

如果你有更具体的场景，可以在评论区问

CodeFlow 适合什么团队？

有持续交付需求、以工单/需求驱动研发的团队：外包与项目制交付、内部平台与工具建设、需要把「需求→交付」链路管到底的研发组织。

能私有化部署吗？

能。平台源码 MIT，单机 4C8G 即可跑全栈；执行器节点 2C2G 即可。数据、代码、模型调用全在你自己的环境内。

必须绑定某家模型吗？

不必。任意 Anthropic 兼容端点都能接（Claude / GLM / Kimi / DeepSeek / 私有模型），账单走你自己的 API key。

支持哪些 Agent 客户端？

Claude Code、Codex CLI、Cursor CLI、Gemini CLI、Qoder CLI / Qoder CLI CN，Provider 适配层可扩展到新客户端。

怎么和我们现有的工单系统对接？

已内置禅道 Provider：绑定产品后需求/缺陷自动拉取，交付报告幂等回写。其他平台实现一个 Provider 接口即可接入。

交付物到底是什么？

可运行的 git 分支与代码、启动/停止/自测脚本、交付报告（含部署路径与验收结果），全部归档在工单里，可下载、可验收、可退回重做。
