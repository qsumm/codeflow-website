案例 1 · 自举（用 CodeFlow 开发 CodeFlow）✅ 真实闭环实测

生产上的登录功能，是数字员工写的

项目背景

我们自己的社区版平台（生产环境在跑）要加「会员登录页记住我」功能，随后又来了一条缺陷：「勾选后刷新页面，勾选状态丢失」。两件事都走 CodeFlow——我们没有自己写。

发生了什么

禅道建单 → 数字员工自主定位真实 git 仓库，自建分支 feat/10007-remember-me：LoginPage 80 行、新建 RememberMeService、3 个测试类，推送分支。缺陷单 52 分钟修复，工单「已关闭」，修复报告幂等回写禅道。

价值：现在生产上跑的这个功能，就是数字员工的交付物——自举不是概念，是我们的日常。

案例 2 · 智能运维模块 · 生产级真机演练📄 生产环境实际发生

真机 nginx 进程死亡：82 秒根因报告，10 分钟恢复

项目背景

真实靶机上故意停掉 nginx（真实业务端口探活失败）。这是对智能运维模块的实战验收——不是回放演示，是真机、真 LLM、真服务。

发生了什么

3 条探活告警同时 firing → 收敛为 1 个事件 → AI 诊断 16 步取证、12.3 万 tokens、8 个只读工具，82 秒出带证据链的根因报告 → 白名单处置、真机重启 → 10 分钟告警到恢复全流程 → 同快照回放两次结论逐字段一致。

价值：值班工程师从"排查 40 分钟"变成"审一份带证据的报告"。

案例 3 · 给 AI Agent 建考场✅ 真实闭环实测

诊断 Agent 改了提示词，怎么知道变好还是变坏？

项目背景

AI 功能的回归测试是个行业难题：改一版提示词，整体是好了还是坏了没人说得清。我们为智能运维模块的诊断 Agent 建了评测平台（EvalDeck）。

发生了什么

故障注入脚本即标注机：每轮真实故障自动变成带标准答案的评测题。版本化数据集 + 11 个预置评估器 + 保留集隔离（调优轮自动排除最终验收题）+ 轮次对比逐字段定位哪几条变差。

价值：AI 功能也能做回归测试——诊断评测闭环已随 v1.8.1 发布。

案例 4 · 从零到可运行✅ 真实闭环实测

真模型 12 分钟交付一个完整小工具

项目背景

一个独立小需求（内部脚本、工具页、小功能），不值得占用整块人力，但要"真的能跑"。

发生了什么

工单写清需求 → 8 秒内派发受理 → 4 步 SDLC 12 分钟跑完 → 可运行代码 + 19 个单元测试全过 + 自动 git 初始化 + 全套文档。边界诚实：坏模型名 40 秒如实 FAILED 交回真人。

价值：小需求不再排队等人，也不用接受一段跑不起来的伪代码。

案例 5 · 多角色流水线✅ 真实闭环实测

开发者 → 评审，双角色零人工接棒

项目背景

评审要求严格的团队，流水线每个角色之间都要人工重新指派——"一个人盯一条流水线"。

发生了什么

双人小队（Developer + Reviewer，workflow 模板定义职责与证据引用）→ SDLC 步骤间自动接棒：成功进下一步、失败按预算重试、END 自动到达 DONE。实测全链路零人工重新指派。

价值：评审门槛没有降——降的是"催活"的人力。

案例 6 · 生产环境实证📄 生产环境实际发生

一台 2 核 2G 的机器，跑着我们整个产品矩阵

项目背景

客户常说：先低成本试起来，数据不能出域。我们的答案不是 PPT，是这台跑了很久的生产机。

实际状态

同一台 2C2G 服务器上：CodeFlow 社区版平台 + 智能运维模块 + MySQL / Redis / MinIO / SeekDB 数据底座，全部自托管在跑。执行器 runtime 纯标准库（Python 3.11），模型接任意 Anthropic 兼容端点，账单走客户自己的 key。

价值：私有化不是降配演示，是可长期运行的生产形态。
