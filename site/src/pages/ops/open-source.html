开源说明

开源包不是主线 dump，
是有防线的发布产物。

你在 GitHub 上看到的每一个开源版本，都经过一条单向发布管道：白名单复制 → 内部文件剥离 → 敏感扫描 → 孤儿快照提交。历史零泄漏是机制保证，不是靠清理。

发布管道

三个仓库位，一条单向流

同步管道（唯一方向）
main（开发真源 · 私有仓：全部历史 + 全部文档）
│ git cherry-pick <需要开源的提交>
▼
opensource-baseline（开源基线分支：AGPL 化 + IP 中性化）
│ python3 tools/oss_export.py
│ ① 白名单复制 ② 内部文件剥离 ③ 运行时产物忽略
│ ④ 敏感扫描（30+ 正则，命中即失败，绝不带病导出）
│ ⑤ 孤儿快照提交（每次导出=全新仓库，零历史泄漏）
▼
oss 仓库（你看到的：快照替换，force push 是设计行为）
①

白名单

开源包只包含白名单路径：代码、部署、工具、用户手册——商业文档、调研、内部交付资料从一开始就不在复制范围。

②

敏感扫描

密钥形态、公网 IP、个人身份、商业词、他方代号——30+ 条正则，任一命中即拦截。真实拦过两次：漏洞披露文档里的公网 IP、演示地址。词表只增不减。

③

孤儿快照

每次导出都是全新仓库的孤儿提交：没有历史、没有内部文件名、没有"删干净了但 git log 里还有"的风险。

机制致谢

不装作原创

本平台的若干核心机制（指纹状态机、诊断 Agent 循环、终态工具契约）在设计调研中参考了 Apache-2.0 许可的开源项目，逐条出处标注在产品仓库的设计文档中——哪些思想来自谁、我们自己改了什么，都有留痕。
