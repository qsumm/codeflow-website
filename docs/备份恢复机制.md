## 四、恢复手册（按场景）

### 场景 1：网站文件损坏 / 误删（最快，~2 分钟）

```bash
# 解包
cd /tmp && tar xzf ~/codeflow-backups/codeflow-backup-2026-11-19.tar.gz
# 回传
rsync -az --delete -e "ssh" /tmp/codeflow-backup-2026-11-19/site/ root@8.148.155.87:/var/www/codeflow-site/
# 验证
curl -s -o /dev/null -w "%{http_code}" https://codeflow.com.cn/   # 应 200
```

### 场景 2：阿里云整机重装 / 迁移新机（~15 分钟）

```bash
# 1. 基础环境（新机为 Alibaba Cloud Linux 3 / CentOS Stream 9）
dnf install -y nginx python3.11
systemctl enable --now nginx

# 2. 解包上传
tar xzf codeflow-backup-2026-11-19.tar.gz -C /tmp
rsync -az /tmp/codeflow-backup-*/site/ root@新机:/var/www/codeflow-site/
ssh 新机 'mkdir -p /opt/codeflow-app/media /opt/site-counter /etc/nginx/ssl'
scp /tmp/codeflow-backup-*/media/* root@新机:/opt/codeflow-app/media/
scp /tmp/codeflow-backup-*/server.py root@新机:/opt/codeflow-app/

# 3. 证书
scp /tmp/codeflow-backup-*/tls-codeflow.com.cn.bundle root@新机:/tmp/
ssh 新机 'cd /etc/nginx/ssl && csplit -z -f codeflow.com.cn- /tmp/tls-codeflow.com.cn.bundle "/----KEY----/" {*} 2>/dev/null; \
  mv codeflow.com.cn-00 codeflow.com.cn.pem; mv codeflow.com.cn-01 codeflow.com.cn.key; chmod 600 *.key'
# （bundle 中证书在前、`----KEY----` 后为私钥；或手工拆分）

# 4. nginx 配置
scp /tmp/codeflow-backup-*/nginx-aliyun-codeflow.conf root@新机:/etc/nginx/conf.d/codeflow.conf
# ⚠️ 若新机 nginx.conf 不含 `include /etc/nginx/conf.d/*.conf;`，需手工加一行

# 5. 后端
ssh 新机 'mkdir -p /root/.config/pip && printf "[global]\nindex-url=https://mirrors.aliyun.com/pypi/simple/\ntrusted-host=mirrors.aliyun.com\n" > /root/.config/pip/pip.conf
cd /opt/codeflow-app && python3.11 -m venv .venv && ./.venv/bin/pip install -q fastapi uvicorn
# .env 从模板重建，密钥从密码管理器抄入：
#   DYPNS_ACCESS_KEY_ID= / DYPNS_ACCESS_KEY_SECRET= / MEDIA_TOKEN_SECRET= / CODEFLOW_REPO_URL=
cat /tmp/codeflow-backup-*/systemd-units.txt'   # 按内容重建两个 unit

# 6. 数据库
scp /tmp/codeflow-backup-*/auth.db root@新机:/opt/codeflow-app/auth.db
scp /tmp/codeflow-backup-*/hits.db  root@新机:/opt/site-counter/hits.db

# 7. 启动与验证
ssh 新机 'systemctl daemon-reload && systemctl enable --now nginx codeflow-site site-counter
curl -s -o /dev/null -w "%{http_code}" -H "Host: codeflow.com.cn" http://127.0.0.1/   # 应 200'
# 8. DNS 指向新机 IP（阿里云云解析控制台）
```

## 九、安全加固档案（2026-11-19 实施）

### 9.1 已落地的防御层

| 层 | 措施 | 配置位置 |
|---|---|---|
| SSH | `PasswordAuthentication no` + `PermitRootLogin prohibit-password`（仅密钥） | `/etc/ssh/sshd_config`（备份 `.bak.2026-11-19`）|
| SSH 爆破 | fail2ban sshd jail：5 次/10 分钟封 1 小时，递增翻倍至 1 天 | `/etc/fail2ban/jail.d/sshd.local` |
| nginx 爆破 | fail2ban：nginx-auth / nginx-botsearch / nginx-limit-req 三 jail | `/etc/fail2ban/jail.d/nginx-auth.local` |
| 短信盗刷 | 发码接口 1 次/分钟/IP（burst 3）；验证码 5r/s（burst 10） | nginx `cf_sms_limit` / `cf_api_limit` zone |
| 媒体滥用 | 令牌/取流 5r/s burst 5 | 同上 |
| PV 刷量 | 30r/s（burst 20） | `cf_pv_limit` zone |
| 应用层压测 | 超限返回 **429**（`limit_req_status 429`），50x.html 兜底页 | 各 location 内 |
| 宝塔面板 | 8888 端口 iptables 仅允许 127.0.0.1（第一规则位） | iptables INPUT 规则 1 |
| 无用服务 | rpcbind（111 端口）已 stop + disable | systemd |

### 9.4 ⚠️ 重要操作须知

1. **SSH 只能密钥登录**：`~/.ssh/id_ed25519`（qym00725@163.com）。密码登录已禁用——**保管好这台 Mac 上的私钥**；若丢失，走阿里云控制台 VNC 救援。
2. **测试 SSH 密码认证时**，本机 `~/.ssh/config` 有 `ControlMaster auto`（连接复用），必须加 `-S none -o ControlPath=none` 才能测出真实行为，否则会复用已认证通道造成误判。
3. **iptables 规则不持久**：重启后第 1 条（8888 DROP）会丢。如需持久化：`iptables-save > /etc/sysconfig/iptables` 并 `systemctl enable iptables`。安全组层（阿里云控制台）8888 本就未放行，故为纵深防御而非唯一防线。
4. **fail2ban 解封自己**：误封时 `fail2ban-client set sshd unbanip <你的IP>`。

### 9.5 fail2ban 封禁规则详解（2026-11-19 快照）

**原理**：fail2ban 持续盯日志，同一 IP 在时间窗口内作恶达阈值 → iptables 在防火墙层 DROP 该 IP 的 80/443/22 包，到期自动解封。

#### 四个 jail 的规则（当前生效值）

| Jail | 监控日志 | 封禁行为（failregex） | 阈值 | 窗口 | 封禁时长 | 递增 |
|---|---|---|---|---|---|---|
| `sshd` | systemd journal | SSH 认证失败（`Failed password` 等） | 5 次 | 10 分钟 | **1 小时** | ✅ 翻倍至 1 天 |
| `nginx-botsearch` | access.log | 扫描探测（404/403/400 计数，如 `/.env` `/admin` `/wp-*`） | 10 次 | 10 分钟 | 10 分钟 | ❌ |
| `nginx-auth` | error.log | 登录认证失败 | 8 次 | 10 分钟 | 30 分钟 | ❌ |
| `nginx-limit-req` | error.log | 触发 nginx limit_req（429 大户） | 50 次 | 10 分钟 | 5 分钟 | ❌ |

封禁动作：`iptables-multiport`（DROP 22/80/443），到期自动解封。

#### 豁免规则（防止误伤）

`nginx-botsearch` 带 ignoreregex：**`/api/v1/*` 路径的所有请求不计入**。
原因：CodeFlow 平台前端（live-screen 等）对 `/api/v1/*` 的周期性轮询含正常 404，
不能当机器人计数。外部扫描器打的路径（`/.env` 等）不在 `/api/v1/` 下，照封不误。

#### 调优决议（2026-11-19 已确认）

- `nginx-botsearch` 维持 **10 分钟**封禁（用户拍板）：轻量封禁策略，避免误关偶尔误触的正常用户；扫描器若持续回来会被反复封禁，等效长期拦截
- `nginx-limit-req` 阈值 50 次合理：其拦截对象是「触发限流还继续打」的顽固者

#### 对正常用户零影响

正常浏览（页面点击 + 资源加载）远达不到任何 jail 的阈值；限流 429 的并发场景
也到不了 50 次/10 分钟封禁线；SSH 密钥登录不计入失败。
